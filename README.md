# Табель 4502 — запуск на GitHub Pages с нуля

Готовый сайт для старосты группы 4502. Все 30 учащихся уже добавлены в вашем порядке. Ничего программировать, собирать или устанавливать для публикации не нужно: достаточно браузера и аккаунта GitHub.

**Правила табеля:** пустая клетка означает присутствие; Б, УП, ПН, СБ, ОМ, Ц и ПР входят в итоговую сумму. Все отметки вы вносите вручную. Обычная пара — 2 академических часа.

Инструкция подготовлена 27 октября 2026 года. Названия кнопок GitHub приведены на английском, как в его интерфейсе.

## Обновление Liquid Glass · 28 октября 2026

Табель оформлен в общем стиле с вашим расписанием: одинаковые шрифтовая схема, цвета, градиентный фон, шапка, стеклянные поверхности и плавные переходы. Есть собственный календарь дат и месяцев, меню темы, плавающий индикатор в переключателях, ползунки и кнопки изменения часов. Поддерживаются светлая, тёмная и системная темы.

**Если табель уже опубликован:**

1. Откройте старый табель → **Настройки → Резервная копия** и сохраните JSON у себя.
2. Распакуйте этот ZIP. В существующем репозитории табеля откройте **Code → Add file → Upload files**.
3. Загрузите **все файлы из архива** на место старых, рядом с `index.html`. Новые `glass.css`, `glass-ui.js`, `academy-light.png` и `academy-dark.png` тоже обязательны. Сам ZIP загружать не нужно.
4. Нажмите **Commit changes** и дождитесь окончания публикации во вкладке **Actions**. Настройки Pages оставьте прежними.
5. Откройте прежний адрес табеля и обновите страницу. На компьютере для обновления без кэша нажмите **Ctrl+Shift+R** или **Cmd+Shift+R**. На телефоне закройте вкладку и откройте сайт снова после публикации. Не очищайте данные сайта.

Удалять репозиторий и предварительно удалять старые файлы не требуется. При обновлении по прежнему адресу в том же браузере журнал остаётся в местном хранилище. При переносе на другой домен или в другой браузер восстановите резервную копию через настройки.

**Несколько причин за день сохранены:** `ПН/2; ПР/2; Б/2` дают по 2 часа в трёх отдельных столбцах и 6 часов в «Всего». Часы каждой причины можно вводить числом, кнопками `−` / `+` или ползунком. Пустое поле означает присутствие.

Если публикуете впервые, следуйте инструкции ниже с шага 1.

## 2. Войдите в GitHub

Если аккаунта ещё нет, откройте [github.com/signup](https://github.com/signup), зарегистрируйтесь и подтвердите адрес электронной почты. Если аккаунт уже есть — просто войдите в него. Платный тариф для описанного ниже способа не требуется.

**Что будет публичным.** В варианте с GitHub Free используются публичный репозиторий и общедоступный сайт. В пакет встроены фамилии группы: их увидит любой посетитель сайта и читатель исходного кода. Вход через ChatGPT для этой версии не нужен. Посещаемость, внесённая через интерфейс, сохраняется только в вашем браузере и не отправляется в GitHub. У другого посетителя будет свой отдельный журнал.

Если фамилии должны быть доступны только вам, этот вариант публикации со встроенным списком не подходит без изменения способа хранения списка. Приватный репозиторий сам по себе не следует считать паролем для сайта Pages.

## 3. Создайте отдельный репозиторий

Репозиторий — это папка проекта на GitHub. Для табеля создайте новую, отдельно от вашего расписания.

1. Откройте [github.com/new](https://github.com/new).
2. В поле **Owner** оставьте свой аккаунт.
3. В **Repository name** введите `tabel-4502`.
4. Выберите **Public**.
5. Включите **Add README** — так сразу появится ветка с файлами.
6. Остальные дополнительные настройки можно оставить по умолчанию.
7. Нажмите **Create repository**.

Имя аккаунта и название репозитория определят адрес сайта. Если `tabel-4502` уже существует, выберите другое свободное имя и учитывайте его в адресе.

## 4. Загрузите файлы

1. В созданном репозитории откройте вкладку **Code**.
2. Нажмите **Add file → Upload files**.
3. Перетащите в окно **сами файлы из распакованного архива**, включая `index.html`, `app.js`, `core.js`, `style.css`, `glass.css`, `glass-ui.js`, `schedule.json`, `icon.svg`, `academy-light.png` и `academy-dark.png`. Инструкции тоже можно загрузить.
4. В сообщении к загрузке напишите, например, `Добавлен табель группы 4502`.
5. Выберите сохранение прямо в основную ветку (**Commit directly to the main branch**) и нажмите **Commit changes**.

**Загружайте содержимое папки, а не ZIP и не внешнюю папку целиком.** На вкладке Code сразу должен быть виден `index.html`, рядом с `app.js` и другими файлами. Не должно требоваться открывать папку `dist` или `github-pages-4502`, чтобы найти главную страницу.

Если файл `README.md` уже был создан на предыдущем шаге, загружаемая инструкция заменит его.

Файл `.nojekyll` может быть скрыт системой. Если вы не смогли загрузить его, создайте на GitHub: **Add file → Create new file**, имя `.nojekyll`, содержимое можно оставить пустым; если редактор требует текст, впишите `static`. Затем **Commit changes**. У этого файла нет расширения `.txt`.

В репозиторий нужны только файлы сайта. Резервные копии `tabel-backup-…json`, выгруженные CSV, PDF и заполненные печатные табели туда не добавляйте: они содержат ваши записи.

## 5. Включите GitHub Pages

1. Вверху репозитория откройте **Settings**. На узком экране эта вкладка может находиться в меню.
2. В левом меню выберите **Pages**.
3. В блоке **Build and deployment** установите параметры:

| Настройка | Значение |
| --- | --- |
| Source | **Deploy from a branch** |
| Branch | **main** |
| Folder | **/ (root)** |

4. Нажмите **Save**.
5. Дождитесь публикации. Она может занять до 10 минут. Обновите страницу Settings → Pages и нажмите **Visit site**, когда кнопка появится.

Если вместо `main` ваша основная ветка называется иначе, выбирайте именно ветку, в которую загрузили файлы. В списке веток нет `main` — сначала убедитесь, что загрузка на шаге 4 сохранена.

Никакой собственный workflow GitHub Actions, сервер, база данных или домен для этого пакета не нужны. GitHub сам выполняет стандартную публикацию Pages.

Адрес имеет вид `https://ВАШ-ЛОГИН.github.io/tabel-4502/`. Например, **если** ваш логин — `qppaza`, адрес будет [https://qppaza.github.io/tabel-4502/](https://qppaza.github.io/tabel-4502/). Этот пример не означает, что сайт уже опубликован: используйте фактическую ссылку из Pages.

## 6. Проверьте первое открытие

1. Откройте **Visit site**, а затем сохраните адрес в закладки.
2. Убедитесь, что указана группа **4502** и во вкладке **Учащиеся** есть 30 человек.
3. Откройте **Табель** и выберите нужный месяц.
4. Нажмите ячейку напротив учащегося и даты. Введите для проверки `Б/4; ПН/2` и сохраните. Если часы превышают занятия в расписании, приложение попросит подтвердить дневной итог.
5. Должно получиться: Б — 4 часа, ПН — 2 часа, всего — 6 часов.
6. Обновите страницу: запись должна остаться. Затем снова откройте эту ячейку и очистите пробную запись.

Другие пустые клетки остаются пустыми. Присутствие отдельно отмечать не требуется. Ни расписание, ни наступление новой даты не создают пропусков автоматически.

## 7. Как вести журнал каждый день

**Ввод по дням.** В разделе «Табель» выберите месяц, нажмите нужную ячейку и впишите `Б/8`, `ПН/2` или несколько причин через точку с запятой: `Б/4; ПН/2`. После сохранения дневные и месячные суммы пересчитаются. Число после `/` — часы, не количество пар. Вводятся целые часы, не более 24 за день.

**Календарь и оформление.** Нажмите дату или месяц, чтобы раскрыть календарь. Заголовок календаря переключает выбор дня, месяца и года. Стрелки листают период; «Сегодня» или «Этот месяц» возвращают текущую дату. Кнопка темы рядом с заголовком «Табель» открывает меню светлой, тёмной и системной темы. Дни недели и переключатель «День / Табель» можно выбирать нажатием или перетаскиванием индикатора. Клавиши стрелок также переключают выбор.

**Ввод по парам.** В разделе «День» выберите дату и занятие, затем нужного учащегося и причину. По умолчанию одна обычная пара даёт 2 часа. Продолжительность занятия можно исправить вручную. Расписание служит подсказкой; отметки вы ставите сами.

**Один итог на день.** Если для учащегося уже есть записи по отдельным парам, сохранение дневного итога за эту дату заменит их. Дневной итог имеет приоритет, поэтому часы не суммируются повторно. Для одной даты у одного человека удобнее придерживаться одного способа ввода.

**Личная история.** Нажмите фамилию учащегося. Откроются его пропуски, разбивка по причинам и итог за выбранный месяц.

**Все причины учитываются.** В итог «Всего» входят Б, УП, ПН, СБ, ОМ, Ц и ПР, в соответствии с вашим правилом. Пустая клетка даёт 0 часов пропусков.

## 8. Сохранение, перенос и резервные копии

После сохранения записи данные остаются в этом браузере. Обычное закрытие вкладки не удаляет их. Однако другой браузер, другой профиль, телефон или другой домен имеют отдельное хранилище. Очистка данных сайта может удалить журнал; режим инкогнито для постоянной работы не подходит.

Для резервной копии: **Настройки → Резервная копия**. Сохраните полученный JSON-файл у себя. Делайте это после важных изменений и перед очисткой браузера или обновлением приложения.

Для переноса: на другом устройстве откройте свой сайт → **Настройки → Восстановить из файла** → выберите JSON → подтвердите замену текущего журнала. Восстановление заменяет данные, а не объединяет две версии.

**Если вы уже заполняли предыдущую версию сайта:** сначала скачайте резервную копию там, затем восстановите её на GitHub Pages. Данные автоматически между разными адресами не переносятся. Этот пакет не содержит ваших введённых отметок — только приложение, исходный список и расписание.

CSV и PDF предназначены для просмотра и печати. Для восстановления всего журнала используйте именно полную JSON-копию. Одновременная общая работа нескольких старост и облачная синхронизация в этой версии не предусмотрены.

## 9. Печать и выгрузка

1. В разделе **Табель** выберите нужный месяц.
2. Нажмите **Выгрузить → Печать / сохранить в PDF**.
3. В окне печати выберите **А4** и **альбомную ориентацию**. Отключите браузерные колонтитулы с адресом страницы и датой, если они мешают.
4. Для файла вместо принтера выберите **Сохранить в PDF**. Для бумаги выберите принтер.

Если окно печати не открылось, разрешите новую вкладку для сайта либо выберите **Скачать печатный табель**. Полученный HTML можно открыть отдельно и распечатать. В печать попадает вся группа, независимо от поиска на экране. Табель помечен как черновик.

Для Excel выберите **Таблица для Excel (.csv)**. Если всё открылось одним столбцом, импортируйте файл как UTF-8 с разделителем «точка с запятой». CSV — отдельная выгрузка; изменения в Excel не возвращаются в сайт.

Для новой копии нажмите **Настройки → Обновить с сайта**. Если исходный сайт недоступен или формат изменился, останется предыдущая копия. Есть и кнопка **Импорт расписания** для JSON или сохранённого HTML источника. Обновление источника не меняет уже записанные часы.

Затем в том же репозитории через **Add file → Upload files** загрузите обновлённые файлы поверх старых и сохраните изменения. Pages опубликует их автоматически. Настраивать Pages заново не требуется. Обычное обновление кода не должно удалять сохранённый журнал; копия нужна для подстраховки.
